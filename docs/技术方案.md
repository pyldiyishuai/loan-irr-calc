# 分期真实利率计算器 · 技术方案

## 一、产品定位

### 用户是谁

| 画像 | 场景 | 核心诉求 |
|---|---|---|
| 下单前犹豫的人 | 页面显示「12 期免息」或「月费率 0.75%」 | 到底贵不贵 |
| 已经办了分期的人 | 想知道自己多付了多少钱 | 一个真实数字 |
| 准备借钱的人 | 在几个渠道之间比较 | 哪个最便宜 |
| 好奇型用户 | 刷到「分期真实利率翻倍」的科普 | 验证真假 |

### 为什么这个需求值钱

1. **搜索全年稳定**，不像个税有季节性 —— 消费信贷是常青需求
2. **信息不对称极大**：销售只报月费率和名义年化，真实成本几乎没人主动说
3. **决策金额大**：一次分期几千到几万，用户对准确性要求高
4. **广告主明确**：银行信用卡、消费金融、理财，都是高预算行业

## 二、核心算法

### 2.1 现金流构造

标准分期：「等额本息 + 固定手续费」

```
每期手续费 = 本金 × 月费率          ← 按初始本金，不随余额递减
每期本金   = 本金 ÷ 期数
每期还款   = 每期本金 + 每期手续费

现金流 = [实际到手, −每期还款 × N]
```

`实际到手 = 本金 − 一次性手续费 − 砍头息`

### 2.2 IRR 求解

```
NPV(r) = Σ CF_t / (1+r)^t = 0
```

对标准贷款现金流，`NPV(r)` 关于 `r` 严格单调递减，二分法必然收敛。

```js
var lo = -0.9999, hi = 10;
for (var i = 0; i < 200; i++) {
  var mid = (lo + hi) / 2;
  var f = npv(cf, mid);
  if (Math.abs(f) < 1e-10) return mid;
  if (f * fLo > 0) { lo = mid; fLo = f; } else { hi = mid; }
}
```

**为什么不用牛顿法**：`NPV` 在 `r → −100%` 附近导数趋于 0，
牛顿法会发散或跳到无意义的解。二分法慢一点（200 次迭代 < 1ms），
但永远收敛。

### 2.3 年化换算

```js
annual = Math.pow(1 + monthly, 12) - 1
```

**不是** `monthly × 12`。后者是名义年化，也就是销售报给你的那个数。

### 2.4 前置费用

前置费用不改变还款额，只减少到手金额。所以它同时抬高 IRR 的分子
（分母变小、分子不变）。效果比同金额的手续费更狠。

## 三、数值验证

借 12,000 / 12 期 / 月费率 0.75%：

```
每期还款 = 1000 + 90 = 1090
总还款   = 13080，手续费 1080

解 12000 = 1090 × [1 − (1+r)^−12] / r
→ r ≈ 1.35%/月
→ 年化 = 1.0135^12 − 1 = 17.48%
```

不同期数的真实年化（同一费率 0.75%）：

| 期数 | 真实年化 | 说明 |
|---|---|---|
| 3 期 | 14.3% | 本金占用时间短 |
| 12 期 | 17.48% | 最常见 |
| 24 期 | 18.2% | 手续费总额翻倍 |

**期数越长，真实年化越高** —— 这一点反直觉，因为很多人以为
「分得越久越轻松」。实际上手续费总额按期数线性增长，
而本金占用时间的增长是次线性的。

## 四、扩展点

### 4.1 多方案并排

**已有接口**：`Core.Irr.comparePlans(plans)`，按真实年化升序返回。
**改哪里**：`ui/` 新建 `multi-plan.js`，表格对比 3–5 个方案。
**场景**：「12 期 vs 24 期 vs 银行消费贷，哪个划算」。

### 4.2 按目标年化反查

**已有接口**：`Core.Irr.maxFeeRateFor(amount, months, targetAnnual)`。
**场景**：「我能接受 10% 以内的成本，最多能承受多高的月费率？」
**UI**：结果区加一行「月费率超过 X% 就不划算了」。

### 4.3 等额本金 / 先息后本

**改哪里**：`core/irr.js` 的 `buildSchedule` 加一个 `method` 参数。
**注意**：这不是换个显示，现金流形态完全不同，IRR 要重算。
房贷场景用等额本金很常见，消费分期基本没得选。

### 4.4 LPR 实时显示

民间借贷 4 倍上限跟着 LPR 走，LPR 一调数字就变。
**改哪里**：`integrations/api.js` 加一个 `lpr` 端点，
`data/loan-presets.js` 的 `benchmarks` 从配置读。

### 4.5 导出还款计划

CSV 比 xlsx 省事：

```js
var csv = rows.map(r => r.join(',')).join('\n');
var blob = new Blob(['\ufeff' + csv], { type: 'text/csv;charset=utf-8' });
```

`\ufeff` 是 BOM，不加 Excel 打开中文会乱码。

### 4.6 分享长图

「月费率 0.75% → 真实年化 17.48%」这个对比本身就适合截图转发。
Canvas 手绘 750×1000：名义 vs 真实双色条 + 倍数 + 二维码。

### 4.7 信贷咨询线索（CPA）

**这是本工具最值钱的变现方式。**
「想找更低成本的资金？」→ 表单 → 转给银行信用卡中心或助贷机构。
**单价**：信用卡开卡 ¥30–200/张，贷款线索 ¥50–500/条。
**注意**：只推持牌机构，不推高利贷 —— 否则工具的公信力就没了。

### 4.8 多语言 / 港澳台

香港的「月平息」（monthly flat rate）和内地口径几乎一样，
同样存在「表面低、实际高」的问题，是个现成的市场。

## 八、已知坑

### 坑 1：名义年化的两种口径

- **简单口径**：月费率 × 12 = 9%（销售用这个）
- **含前置费用**：总费用 ÷ 到手 ÷ 年数（更接近真实，但仍不是 IRR）

结果页三个口径要分清楚，别混着显示。

### 坑 2：零利息测试用例容易写错

`[1000, -100 × 12]` 不是零利息 —— 借 1000 还 1200。
零利息应该是 `[1200, -100 × 12]`。
写测试时先把现金流在纸上列出来。

### 坑 3：期数越长真实年化越高

很多人以为反过来。原因是手续费总额按期数线性增长，
而本金占用时间的增长是次线性的（1/n 的调和性质）。

### 坑 4：提前还款的两种口径差很多

- 理想口径：只还剩余本金
- 多数产品：剩余本金 + 剩余全部手续费

两者可能差几千块。**必须两种都算给用户看**，并提示先问客服。

### 坑 5：JS 生成的元素不能直接 getElementById

`rateNominal` / `rateReal` 这两个 id 在对比条里是动态生成的，
HTML 里不存在。`document.getElementById` 返回 null，
测试里直接取 `.textContent` 会抛错。要么用容器文本，要么先渲染。
